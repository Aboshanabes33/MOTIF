# Groq transcription, open PR only

Default provider: Groq whisper-large-v3, direct main-process HTTPS to the fixed Groq transcription endpoint. Selected for error-sensitive multilingual work per Groq docs, not an independently tested Arabic benchmark. No real key available, no Groq request made, no real Arabic quality claim. Arabic text in tests is a mocked response only.

Updated per owner clarification Nov26,13:38: owner testing his own build supplies GROQ_API_KEY in a backend-only platform env file, not an in-app key field. This supersedes the first version of this PR's per-user safeStorage input. No key was supplied to us.

Copy .env.example to .env.windows, .env.macos or .env.linux. Development path: project root. Packaged path: Electron app.getPath('userData'), The exact current backend file path is shown in Transcription settings, since app naming and userData relocation can change it. Only that fixed platform file is read, not cwd searches, renderer input, MCP paths or process.env fallback. Changes are reread on status/job, no app restart required for key changes. Provider preference alone is stored in non-secret JSON. Files are git-ignored and explicitly excluded from packaging. The committed example has an empty value only.

Env file is plaintext under the owner's control, NOT OS-encrypted storage and NOT safely distributable with a key. Restrict local filesystem permissions/ACLs. Never embed the file in app.asar/exe or send it to other users. This implements local-owner testing, not a shared server/proxy or a safely shared account for all app users. Existing previously saved encrypted key files, if any from an earlier development build, are ignored, not silently migrated or deleted. No key was ever installed in our test environment.

No key entry, readback, replacement or deletion IPC/UI exists now. Strict schemas reject key-bearing save requests. Main reads only GROQ_API_KEY using Node's env parser; unrelated variables never enter process.env or spawned FFmpeg environment. Missing/invalid/oversize/directory/symlink files fail with a generic message, no input echo. UI returns only configured/not-configured status, not file contents or key. No API verification is implied by configured status.

Audio disclosure appears in settings, source button, status sidebar, MCP descriptions and native per-job approval, default Cancel. Your Groq account controls tier/billing. App cannot prove the account is free-tier and does not upgrade plans. No automatic retries and no silent provider fallback.429 produces quota/rate error and numeric Retry-After advice,401/403 key/access error,413 size error,5xx/network/timeouts clear failures. No vendor error bodies echoed. Fixed HTTPS endpoint rejects redirects,60-second request timeout,1MiB bounded JSON response with segment schema validation. No remote URL uploads, only extracted local audio. Manual local Whisper fallback retains existing cached large-v3-q5_0 pipeline.

Scope remains first60seconds, clearly labeled, NOT full long-video transcription. FFmpeg extracts10-second16kHz mono PCM chunks(~320KB), max6, each checked under20MiB to stay below documented free-tier25MB. A2GiB source video can be reduced safely without uploading video. Independent nonoverlapping chunks may lose words at boundaries; no overlap reconciliation claim. Timestamps offset back into source. Temporary WAVs removed on success/failure/cancel. Cancellation aborts network requests and kills local extraction; job is not marked succeeded after cancellation. Returned transcript remains uncorrected in project and can feed existing bounded HyperFrames captions. No local model required for Groq; FFmpeg still required. Local-only tasks remain local.

Verification: TypeScript/build and mocked HTTP tests for fixed multipart/model, limits, error sanitizing,429 no retry,invalid payloads,backend env missing/valid/empty/oversize/status and provider-only persistence,real FFmpeg extraction+mocked Groq offset transcript,cleanup,cancelled-vs-failed persisted job states. Electron UI smoke and screenshot inspected. No Windows execution, real key verification or provider e2e. No release/merge/CI/spend.
